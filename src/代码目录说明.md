# src/ 目录说明 — 脚本组织与运行约定

> 本目录按架构的**双流水线**组织成 4 个包 + 1 个入口文件,与 [开发路线与学习计划.md](../开发路线与学习计划.md) 的 D0~D9、[系统架构说明.md](../系统架构说明.md) §3/§4 一一对应。

## 目录结构

```
src/
├── common/               # 共享基础(两条流水线都用)
│   ├── config.py         #   全部路径/参数常量 —— 单一事实来源,任何模块不写死路径
│   └── utils.py          #   JSONL 流式读写、大文件 sha1(已实现,可直接用)
│
├── offline/              # 离线流水线(建库,路线计划 D0→D4,跑一次管数月)
│   ├── download.py       #   D0 下载 dump + 断点续传 + sha1 校验
│   ├── parse.py          #   D1 抽取 + 二次清洗 + 繁简统一 + 合并 → wiki_zh.jsonl
│   ├── chunk.py          #   D2 450~550 弹性滑窗切片 → wiki_chunks.jsonl(命门模块)
│   ├── embed.py          #   D3 Ollama 向量化 + L2 归一化(核心)
│   └── index_build.py    #   D4 IndexFlatIP 建库 + 元数据落盘
│
├── online/               # 在线流水线(查询,路线计划 D6,每次提问都走)
│   ├── retrieve.py       #   ①② 向量检索 top-50 + 元数据回填
│   ├── rerank.py         #   ③ 重排(D6 标配,原 W5 进阶;方案 A cross-encoder / B LLM-as-reranker)
│   └── qwen.py           #   ④ prompt 组装 + Qwen 生成 + token 预算
│
├── agent/                # 单 Agent + 检索工具(D9,只定接口,未落盘)
├── pipeline.py           # 端到端编排入口:ask("问题") → 带引用的答案
├── evaluation/           # 评估(路线计划 D8)
│   └── eval.py           #   评测集构造 / hit@k / MRR / A/B 对比
├── check_env.py          # 环境自检(已 7 项 PASS)
└── 代码目录说明.md       # 本文件
```

## 运行约定(重要)

**方式一:编辑器内运行** —— 把 `src` 标记为源码根(或配好 `pythonpath=src`),任意文件直接 Run 即可,包导入自动生效。

**方式二:命令行(macOS)** —— 先激活 venv,再在 **src 目录**下用 `-m` 方式运行:

```bash
cd ~/program/LLM/agent/rag-from-scratch   # 以本机实际仓库路径为准
source .venv/bin/activate
cd src
python -m offline.download      # D0 下载
python -m offline.parse         # D1 清洗
python -m offline.chunk         # D2 切片
python -m offline.embed         # D3 向量化
python -m offline.index_build   # D4 建索引
python -m evaluation.eval       # D8 评估
```

## 三条编码约定

1. **路径与参数只从 `common.config` 取**——改参数(如块长 500→300)只改一处,全系统生效
2. **数据文件一律 JSONL、一律流式**——语料 GB 级(维基 jsonl 约 2.3~3.8 GB),禁止整读进内存(`common.utils.iter_jsonl` 已备好)
3. **每个模块可独立运行**(`if __name__ == "__main__"`),也可靠导入被 pipeline 编排——离线各步骤天然是命令行任务
